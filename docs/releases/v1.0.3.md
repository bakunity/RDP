# Hermes RDP v1.0.3

Hotfix чистой установки серверной части.

## Исправлено

На чистом сервере `/etc/frp/frps.toml` ещё отсутствует. В `v1.0.2` установщик пытался прочитать из него legacy token без проверки существования файла. При включённом `set -o pipefail` команда `sed` завершалась с кодом `2`, поэтому установка останавливалась после загрузки FRP и до создания systemd-служб.

В `v1.0.3` legacy-конфиг читается только тогда, когда файл действительно существует. При чистой установке создаётся новый случайный FRP token.

## Совместимость

- повторный запуск после частичной установки `v1.0.2` безопасен;
- уже созданный `/etc/hermes-rdp/frp-token` повторно не генерируется;
- API, SQLite registry, Windows agent и стандартные порты не изменены.
