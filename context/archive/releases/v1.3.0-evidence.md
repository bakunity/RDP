## Product capability added in v1.3.0

v1.3.0 adds a backward-compatible optional trusted public-IP certificate lifecycle for the Windows RDP listener:

- server-side Let’s Encrypt short-lived public-IP certificate issuance;
- Hermes-owned renewal service/timer;
- non-secret server certificate state;
- authenticated certificate-package delivery to registered devices;
- Windows certificate import and CUSTOM `RDP-Tcp` binding;
- LocalSystem low-frequency certificate rotation worker outside the main Agent loop;
- automatic listener drift detection/recovery;
- Fresh Install, transactional Update and existing-device Repair integration;
- Uninstall cleanup of both main and certificate-rotation runtime.

The trusted-certificate path requires a globally routable public IPv4 and reachable TCP 80 for ACME HTTP-01 when enabled. Existing OpenSSH-only installations remain valid without enabling it.

## Important confirmed bugs resolved during the cycle

1. Windows default self-signed RDP binding is not equivalent to assigning its thumbprint as an explicit CUSTOM binding. Correct rollback removes the explicit custom binding so Windows restores the default state.
2. Localized Windows `SYSTEM` account names must not be compared as English strings; LocalSystem SID `S-1-5-18` is the accepted identity check.
3. A SYSTEM-owned global rotation mutex can block administrator setup preflight unless the existing worker is stopped first and the mutex ACL explicitly permits LocalSystem + Builtin Administrators.

All three bugs have code, CI and bounded live acceptance for their corrected behavior.
