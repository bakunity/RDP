# Hermes RDP v1.2.0 — draft

Статус: **черновик стабилизационного релиза**. Этот файл фиксирует уже live-accepted scope, но не является опубликованным release note до финального release PR/tag.

## Общий результат

`v1.2.0` стабилизирует OpenSSH-архитектуру `v1.1.0` и закрывает основные lifecycle, compatibility, update, security и recovery-сценарии без возврата FRP.

## Подтверждено

### Windows compatibility

- Windows 10 x64 + 32-битный Windows PowerShell: native Microsoft OpenSSH корректно разрешается через Sysnative;
- fresh install из x86 PowerShell прошёл end-to-end acceptance;
- Windows Server 2019 fresh install и последующий Hermes RDP прошли PASS;
- existing-install guard не позволяет `Добавить ПК` разрушить уже зарегистрированный клиент.

### Dashboard / control truth

- desired access и queued command меняются согласованно;
- dashboard отдельно показывает heartbeat агента, desired/applied access, SSH transport и public endpoint;
- Linux listener является authoritative truth для public endpoint;
- `OFF`, `ON`, `RESTART` live-accepted;
- dashboard обновляет command/tunnel state автоматически;
- mobile layout control buttons принят в live usage.

### RDP classification и multi-device

- direct LAN/VPN RDP и Hermes RDP классифицируются раздельно;
- несколько Windows-клиентов одновременно держат независимые endpoints;
- два Microsoft RDP-сеанса к разным Hermes devices работали одновременно;
- controlled failure одного устройства не нарушил active RDP другого устройства.

### Performance stabilization

До optimization были подтверждены тяжёлые NetTCPIP/WMI операции в telemetry loop. После optimization ordinary fast path использует более лёгкие primitives и cache.

Live evidence:

- combined fast core на acceptance Windows выполнялся в среднем примерно за десятки миллисекунд;
- heavy resources собираются реже в фоне;
- `НАБЛЮДАТЬ 60с` временно повышает telemetry detail и затем возвращается в background mode;
- пользователь подтвердил, что обычная работа через Hermes RDP стала плавной без заметных прежних микрофризов.

### Lifecycle / recovery

Live-accepted:

- Windows reboot recovery;
- Linux server reboot recovery;
- temporary Windows-side tunnel loss auto-recovery;
- controller restart без обязательного restart RDP transport;
- dedicated Hermes sshd restart с автоматическим reconnect clients;
- `RESTART` возвращает один Hermes SSH transport;
- four-device endpoint health и concurrent RDP;
- one-device failure isolation.

`RL-006` остаётся только PARTIAL PASS: пять repeated sshd cycles были чистыми server-side, но на exact original Windows fixture не был снят финальный one-process count. Stress повторять не требуется.

### Security / device lifecycle

- unique per-device Ed25519 identities;
- cross-device isolation;
- hard delete отзывает server-side device access;
- deterministic safe reuse освобождённого RDP-порта;
- owner-limited Telegram authorization;
- admin SSH `:22` отделён от Hermes tunnel sshd `:7000`;
- Hermes не требует Microsoft Defender exclusions/disable;
- acceptance Windows работала с включённой real-time protection.

`SEC-004` честно остаётся `NOT LIVE-EXERCISED / FIXTURE UNAVAILABLE`: старый deleted raw-client fixture отсутствует, и отозванные credentials не реконструируются искусственно ради теста.

### Transactional server updater

- legacy bug, где backup не включал SQLite, исправлен;
- updater сохраняет consistent database snapshot и rollback provenance;
- successful live update сохранил device state/endpoints;
- deliberate post-mutation failure вызвал automatic rollback с восстановлением app/config/units/database/services/endpoints.

### Transactional Windows updater

- successful update сохранил Device ID, config, Ed25519 identity, `known_hosts`, port и task identity;
- deliberate post-mutation failure вызвал `ROLLBACK=PASS` и вернул previous agent/runtime;
- Windows PowerShell 5.1 compatibility проходит CI.

### Existing-device Repair

Добавлен отдельный repair flow для уже зарегистрированного Windows client.

Repair:

- не выполняет fresh pairing;
- не создаёт второе устройство;
- сохраняет Device ID/API-token/Ed25519 identity/`known_hosts`/RDP port;
- может восстановить missing/broken Hermes Agent и Scheduled Task;
- использует selected-device guard;
- делает bounded readiness check;
- при post-mutation failure восстанавливает previous agent/task snapshot.

Live acceptance:

- controlled removal agent/task/runtime -> `REPAIR=PASS`;
- controlled failure после candidate mutation -> `ROLLBACK=PASS`;
- после обоих сценариев обычный Microsoft RDP снова подключился.

Потеря `device.json`, private key или `known_hosts` намеренно не лечится обычным Repair: automatic owner rekey/recovery остаётся отдельной будущей задачей.

### Telegram Repair / pairing retry UX

PR #25 live-accepted:

- карточка existing device получила **🛠 ВОССТАНОВИТЬ КЛИЕНТ**;
- repair screen показывает выбранный device/endpoint и immutable repair command, bound to selected Device ID;
- generated command передаёт repair parameters полностью;
- fresh pairing остаётся отдельным flow;
- **🔁 НОВЫЙ КОД** создаёт новый one-time pairing code и одновременно обновляет installer command;
- pairing secrets не записываются в durable context/evidence.

## Evidence rules

- **PASS / CONFIRMED** — есть runtime output, CI или явное user confirmation;
- **PARTIAL PASS** — часть acceptance подтверждена, но не весь exact condition;
- не публиковать hypothesis как готовый факт;
- не хранить pairing codes, API tokens, private keys или ready-to-use secret material.
