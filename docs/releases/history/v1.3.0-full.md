# Hermes RDP v1.3.0 — full engineering history

Status: release engineering record for the v1.3.0 tree.

Base release: **v1.2.1**.

## Release scope

v1.3.0 turns the previously self-signed Windows RDP listener certificate into an optional, automatically managed trusted public-IP certificate lifecycle while preserving the existing OpenSSH transport, per-device identities and normal Windows lifecycle semantics.

The work spans Linux certificate issuance/renewal, authenticated certificate delivery, Windows import/binding/rollback, automatic rotation, Fresh Install, Update, Repair, Uninstall, security boundaries, release automation and public documentation.

## 1. Server trusted public-IP certificate lifecycle

A Hermes-owned server path was added for public-IP RDP certificates:

- isolated Certbot installation under `/opt/certbot`;
- public TCP 80 / standalone ACME HTTP-01 validation;
- Let’s Encrypt staging issuance before first production issuance;
- `shortlived` public-IP profile;
- RSA 2048 certificate with Server Authentication EKU;
- certificate/private-key public-key match validation;
- local trust-chain validation;
- Hermes-owned `hermes-rdp-cert-renew.service` / `.timer`;
- bounded renewal wrapper with `flock`;
- non-secret `trusted-rdp-cert-state.json` refresh after successful renewal;
- server installer option `--trusted-rdp-cert` requiring a globally routable public IPv4.

The RDP certificate lifecycle is independent from the HTTPS API certificate. Changing API TLS alone does not remove the Microsoft Remote Desktop listener warning.

### Server acceptance

Confirmed live:

- public TCP 80 reachability;
- staging issuance;
- production issuance;
- SAN/EKU/key/chain checks;
- renewal configuration and not-due renewal smoke;
- renewal timer enabled/active;
- TCP 80 free after bounded operations;
- existing production lineage reused during productization without unnecessary reissuance.

## 2. Authenticated Windows certificate delivery and listener binding

A device-authenticated API path and bounded root helper were added to deliver the current trusted certificate package to a registered Windows device.

Windows `sync-rdp-certificate.ps1` performs:

- pinned HTTPS and bearer-device authentication;
- package validation;
- import into `LocalMachine\My` without the normal exportable flag;
- required private-key Read access for `NETWORK SERVICE` / TermService;
- Windows RDP listener CUSTOM certificate binding;
- post-bind verification and rollback on failure.

The server stores no Windows private identity. The trusted certificate private key exists as ACME/server certificate material and is only exposed through the authenticated bounded certificate-package path when needed.

### Non-exportable boundary

The Windows private key is imported without ordinary exportable behavior. This reduces normal API exportability but is **not** claimed to protect against a fully compromised Administrator/SYSTEM endpoint.

## 3. Default self-signed rollback bug found and fixed

Live rollback testing found an important Windows listener distinction.

The original listener had:

- `SSLCertificateSHA1HashType = 1` (`DEFAULT_SELF_SIGNED`);
- no explicit CUSTOM registry binding.

Attempting to restore that old default self-signed thumbprint through the CUSTOM CIM setter failed with `HRESULT 0x80041008`.

Root cause: Windows default self-signed state is not represented as an explicit custom binding.

Correct rollback:

- remove the explicit CUSTOM registry binding;
- let TermService return to its default self-signed certificate state;
- verify the exact original thumbprint/type and TCP 3389.

This corrected rollback was live-accepted, followed by successful trusted certificate reapply and a fresh externally trusted RDP connection.

## 4. Automatic certificate rotation

Automatic rotation was deliberately kept outside the main Hermes Agent 3-second loop because earlier heavy work in that loop caused real RDP micro-freezes.

A separate low-frequency Windows worker was introduced:

- `client/HermesRdpCertRotation.ps1`;
- Scheduled Task `Hermes RDP Certificate Rotation`;
- LocalSystem execution;
- default low-frequency status checks;
- authenticated non-secret status request first;
- full PFX sync only when the desired thumbprint differs or local listener drift is detected;
- global mutex to prevent duplicate rotation work.

### Localized SYSTEM validation

Windows account display names are localized. Task validation therefore resolves the principal to LocalSystem SID `S-1-5-18` rather than comparing the literal English string `SYSTEM`.

### Global mutex upgrade bug

Live setup upgrade found another real issue: an existing SYSTEM worker could own `Global\HermesRdpCertificateRotation` with an ACL that denied Administrator preflight access.

The failing setup rolled back correctly.

Fix:

- bounded stop of the existing rotation task before preflight/replacement;
- explicit mutex ACL permitting only LocalSystem SID `S-1-5-18` and Builtin Administrators SID `S-1-5-32-544` with required synchronization/modify rights.

The fix passed CI and live revalidation.

## 5. Automatic drift recovery

A controlled Windows test deliberately returned the RDP listener to self-signed/default state while leaving the trusted desired server certificate unchanged.

Observed:

- worker detected local drift;
- status-first path escalated to full sync;
- worker reported `CERT_ROTATION=UPDATED`;
- trusted CUSTOM listener was restored;
- TCP 3389 remained healthy;
- fresh Microsoft Remote Desktop was trusted again without the self-signed warning.

This synthetic drift test closes the automatic recovery behavior. It does not need routine repetition without a relevant regression.

## 6. CERT-013 — normal Windows lifecycle integration

PR #32 integrated the accepted certificate companion into the ordinary Windows lifecycle so users do not need a separate manual certificate setup command.

### Fresh Install

Fresh installer now:

- resolves the requested repository ref to one immutable SHA;
- stages/parses the main Agent and certificate setup before pairing/runtime mutation;
- installs the Agent and establishes stable OpenSSH runtime;
- runs certificate lifecycle setup from the same SHA before final success;
- keeps the existing revoke/snapshot failure boundary.

### Transactional Update

Windows Update now:

- stages/parses Agent + certificate setup from the same immutable SHA;
- records candidate certificate-setup hash in update metadata;
- applies certificate lifecycle before final `UPDATE=PASS`;
- relies on certificate setup self-rollback plus the outer main-Agent/runtime rollback if the sub-operation fails.

### Repair

The previously accepted Repair implementation is preserved as `repair-client-core.ps1`.

The public Repair wrapper:

- resolves Repair core + certificate setup from one immutable SHA;
- snapshots main Agent/task state;
- runs the accepted Repair core;
- then manages certificate lifecycle;
- if certificate setup fails, its own state self-rolls and the wrapper restores the main Agent/task snapshot.

Identity/config/device/port semantics remain in the accepted Repair core.

### Uninstall

Normal uninstall now stops/unregisters:

- `Hermes RDP Agent`;
- `Hermes RDP Certificate Rotation`;
- Agent/rotation/Hermes SSH runtime processes;
- then archives/removes the active Hermes client directory according to the established uninstall behavior.

Server-side device deletion remains separate and is required to revoke device token/public key and free the endpoint.

## 8. Compatibility retained

v1.3.0 keeps the accepted compatibility baseline:

- Windows PowerShell 5.1;
- Windows 10 x64 when installer/Repair is launched from x86/SysWOW64 PowerShell through Sysnative/native OpenSSH paths;
- Windows Server support;
- Microsoft Defender coexistence without exclusions/disablement;
- per-device Ed25519 identity;
- independent administrative SSH and Hermes tunnel sshd;
- transactional server/client update rollback;
- existing-device Repair identity boundary;
- fast main Agent loop without certificate work.

## 9. Security boundaries retained or strengthened

- API HTTPS pinning remains independent from Windows RDP TLS;
- SSH host key remains pinned through the already pinned API path;
- device key remains server-restricted to its assigned endpoint;
- full certificate package requires authenticated device access;
- normal rotation checks expose only non-secret certificate state;
- certificate worker runs under LocalSystem with bounded mutex ACL;
- trusted listener certificate improves endpoint identity verification but does not replace Windows credentials, NLA or authorization.

## Breaking changes / migration

No intentional breaking change relative to `v1.2.1`.

Trusted RDP certificate lifecycle is opt-in on the server. Enabling it requires:

- globally routable public IPv4 used by clients;
- TCP 80 reachable for standalone ACME HTTP-01;
- ability to reach Let’s Encrypt.

Existing OpenSSH-only installations can continue without enabling trusted RDP certificates.
