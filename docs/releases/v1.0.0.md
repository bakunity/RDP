# Hermes RDP v1.0.0

Дата выпуска: **6 августа 2026 года**

Первый стабильный релиз самостоятельного multi-PC RDP-шлюза через один Linux-сервер с Telegram-управлением.

## Главное

Hermes RDP v1.0.0 переводит первоначальную одно-компьютерную схему в полноценную систему устройств:

- сервер Hermes — единственный специальный узел;
- «Windows-PC-01» и все следующие ПК используют одинаковый клиент;
- каждому компьютеру назначается постоянный RDP-порт;
- один Telegram dashboard управляет и показывает состояние всех устройств;
- ON/OFF/RESTART применяется только к выбранному ПК;
- FRPS остаётся включённым для остальных клиентов.

## Возможности

### Multi-PC

- автоматический реестр Windows-компьютеров;
- уникальный `device_id`;
- персональный API token;
- автоматический или заранее выбранный RDP-port;
- отдельная telemetry и command queue;
- переименование и отзыв устройств.

### Telegram dashboard

- одно редактируемое сообщение;
- список ONLINE/OFFLINE устройств;
- экран конкретного ПК;
- LIVE-обновление каждые 3 секунды;
- ON, OFF, RESTART;
- добавление нового ПК;
- подтверждение удаления.

### Windows telemetry

- CPU;
- RAM;
- диск C;
- сетевые counters;
- default route;
- uptime;
- interactive user и sessions;
- RDP connections и remote addresses;
- FRPC state;
- endpoint availability;
- top processes.

### Установка

- server installer для Ubuntu/Debian;
- единый Windows installer;
- миграция legacy Hermes setup;
- автоматическая установка FRP `0.70.1`;
- SHA-256 verification архивов;
- systemd services;
- Windows Scheduled Task;
- backup до изменения файлов.

## Архитектура

```text
Windows agents ── HTTPS telemetry/commands ──> Hermes API + SQLite
Windows FRPC   ── TLS FRP tunnels ───────────> Hermes FRPS
Telegram user  <─────────────────────────────> Hermes Telegram bot
```

Windows-компьютеры не имеют входящего control port: команды приходят в ответе на исходящий telemetry POST.

## Стабильная установка сервера

Скачать:

```bash
curl -fsSL https://raw.githubusercontent.com/bakunity/RDP/v1.0.0/scripts/install-server.sh -o /tmp/install-hermes-rdp.sh
```

Скрыто считать Telegram token:

```bash
read -rsp 'Telegram bot token: ' TG_TOKEN; echo
```

Новая установка:

```bash
sudo env HERMES_RDP_REF=v1.0.0 bash /tmp/install-hermes-rdp.sh --host SERVER_IP_OR_DOMAIN --telegram-token "$TG_TOKEN" --telegram-chat-id TELEGRAM_USER_ID
```

Миграция текущего Hermes:

```bash
sudo env HERMES_RDP_REF=v1.0.0 bash /tmp/install-hermes-rdp.sh --host SERVER_IP_OR_DOMAIN --telegram-token "$TG_TOKEN" --telegram-chat-id TELEGRAM_USER_ID --migrate
```

Проверка:

```bash
sudo hermes-rdpctl doctor
```

## Подключение текущего «Домашнего ПК»

На Hermes сохранить endpoint `SERVER_IP_OR_DOMAIN:53389`:

```bash
sudo hermes-rdpctl pair create --name 'Windows-PC-01' --port 53389
```

На Windows PowerShell от администратора:

```powershell
$u='https://raw.githubusercontent.com/bakunity/RDP/v1.0.0/scripts/install-client.ps1'; & ([scriptblock]::Create((irm $u))) -Server 'SERVER_IP_OR_DOMAIN' -PairCode 'PAIR_CODE' -Fingerprint 'FINGERPRINT' -Name 'Windows-PC-01' -RepositoryRef 'v1.0.0'
```

## Добавление следующего ПК

В Telegram нажать `➕ ДОБАВИТЬ ПК`, затем выполнить выданную команду на новом Windows-компьютере от администратора.

Пример распределения:

```text
Windows-PC-01 → SERVER_IP_OR_DOMAIN:53389
Ноутбук     → SERVER_IP_OR_DOMAIN:53390
Офисный ПК  → SERVER_IP_OR_DOMAIN:53391
```

## Обновление

Server:

```bash
curl -fsSL https://raw.githubusercontent.com/bakunity/RDP/v1.0.0/scripts/update-server.sh -o /tmp/update-hermes-rdp.sh
sudo env HERMES_RDP_REF=v1.0.0 bash /tmp/update-hermes-rdp.sh
rm -f /tmp/update-hermes-rdp.sh
```

Windows:

```powershell
$u='https://raw.githubusercontent.com/bakunity/RDP/v1.0.0/scripts/update-client.ps1'; & ([scriptblock]::Create((irm $u))) -RepositoryRef 'v1.0.0'
```

## Миграция с legacy setup

- server installer создаёт backup в `/var/backups/hermes-rdp/<timestamp>`;
- старый `hermes-rdp-bot.service` отключается только с `--migrate`;
- существующий FRP token и совместимые TLS files импортируются, когда это возможно;
- Windows installer удаляет старые tasks `Hermes FRPC Client`, `Hermes Windows Monitor` и `Hermes RDP Telegram Bot`;
- новый общий task называется `Hermes RDP Agent`;
- порт `53389` можно сохранить через preferred pairing port.

Полный guide: [MIGRATION.md](../MIGRATION.md).

## Безопасность

- TLS 1.2+ API;
- exact certificate fingerprint pinning;
- one-time pair code с TTL 15 минут;
- отдельный API token каждого device;
- SHA-256 token storage;
- Telegram allowlist одного user ID;
- protected Windows ACL;
- forced FRP TLS и собственная CA;
- ограниченный FRP remote-port range;
- непривилегированные Linux service users.

## Известные ограничения

1. FRP token общий для всех клиентов. При утечке `frpc.toml` нужен rotation общего token.
2. Публичные RDP endpoints требуют сильных Windows credentials, NLA и обновлённой ОС.
3. Поддерживаются 64-битные Windows Pro, Enterprise и Education; Windows Home не является RDP host.
4. По умолчанию диапазон содержит 32 устройства.
5. SQLite schema migrations до v1.0.0 не имеют отдельной version table; это направление для следующего релиза.

## Проверки релиза
