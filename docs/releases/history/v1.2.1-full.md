# Hermes RDP v1.2.1 — Full engineering history

Этот файл сохраняет расширенную инженерную историю полного `v1.2.x` stabilization tree. Публичное описание GitHub Release намеренно короче.

## Что представляет собой v1.2.1

`v1.2.1` — рекомендуемый stable release линии `v1.2.x`. Он публикует полный согласованный stabilization tree, подготовленный вокруг `v1.2.0`, и одновременно исправляет release-packaging дефект, из-за которого исторический tag `v1.2.0` оказался привязан не к полному validated tree.

Между `v1.1.0` и полным деревом `v1.2.1` накопилось 283 commit'а. Изменения затронули Windows Agent/installer/update/repair, Linux API/controller/database/tunnel code, Telegram UX, сайт, release automation, основную документацию, durable context/evidence и regression/soak tests.

## Release integrity

В одном release tree согласованы `VERSION`, package `__version__`, `server/pyproject.toml`, `CHANGELOG.md`, release notes, README, архитектурная/operational документация, validated scenarios и regression tests.

## Recovery / transport stability

Проверены Windows reboot, Linux reboot, Windows-side SSH transport loss, dedicated Hermes sshd restart, controller restart без необходимости ронять существующий transport, repeated reconnect cycles, несколько independent Windows devices и one-device failure isolation.

## Soak-time bugs

- CP-001: stalled TLS client мог блокировать HTTPS API acceptance. TLS handshake перенесён в bounded per-connection worker; live health requests сохранили responsiveness.
- CL-001: desired OFF + local ON мог зациклить reconciliation. Control polling отделён от transport recovery; fixture стал детерминированно сходиться OFF/ON.
- CU-001: stale command мог оставаться executing. Добавлены deterministic timeout и late-result guard.

## Windows compatibility

### Win10 x64 + 32-bit PowerShell

На реальном Win10 Pro build 19045 воспроизведён SysWOW64 PowerShell. Installer/Repair используют `Sysnative` для native `ssh.exe`/`ssh-keygen.exe` и canonical System32 path для SYSTEM Scheduled Task. Fresh install прошёл end-to-end.

### Windows Server 2019

Исправлен ProductType gate. Windows Server 2019 Datacenter прошёл fresh install, update с сохранением identity и реальный Microsoft RDP.

### Existing-install safety

Duplicate Add на уже установленной машине больше не выполняет destructive actions и не останавливает рабочую task до pairing failure.

## Transactional lifecycle

### Linux server updater

Requested ref разрешается в immutable SHA. До mutation создаются consistent SQLite backup, app/config/systemd backup и metadata. После update работает bounded health gate; deliberate failure подтверждает automatic rollback.

### Windows updater

Candidate скачивается по immutable SHA и парсится до остановки runtime. Сохраняются Agent/Task snapshot, identity/config/keys/known_hosts/port; bounded readiness и rollback проверены live.

### Existing-device Repair

Repair не делает fresh pairing/rekey. Он сохраняет Device ID, API token, Ed25519 identity, `known_hosts` и порт. Удалённые Agent file + Scheduled Task были восстановлены live; deliberate failure подтвердил rollback. Потеря critical identity приводит к остановке, а не скрытому созданию нового device.

## Performance

Heavy NetTCPIP/WMI/process probes были причиной заметных RDP micro-freeze. Ordinary fast path переработан, heavy telemetry выполняется реже, observation mode bounded. Fast core измерялся десятками миллисекунд, после чего пользователь подтвердил плавную RDP работу.

## Multi-device / endpoint lifecycle

Live проверены simultaneous reverse SSH tunnels, постоянные per-device endpoints, два Microsoft RDP-сеанса одновременно, one-device failure isolation, hard delete с отзывом authorization и освобождением порта, а также безопасный port reuse.

## Telegram control / UX

OFF закрывает listener, ON восстанавливает tunnel, RESTART заменяет transport и возвращает один tunnel. Heartbeat отделён от access state, desired/applied/tunnel state отображаются отдельно, endpoint status server-authoritative. Dashboard автоматически обновляется, mobile layout исправлен, добавлены Repair и new-code actions.

## Security

Сохраняется per-device Ed25519 trust model: private key остаётся на endpoint, cross-device SSH authorization запрещён, admin SSH и Hermes sshd изолированы, OFF/DELETE закрывают public listener. Hermes не требует Defender exclusions; real-time coexistence проверена live.

## Documentation / knowledge retention

Существенно обновлены README, Architecture, Quick Start, Linux/Windows install guides, Migration, Operations, Security, Troubleshooting, Testing A-to-Z, `VALIDATED_SCENARIOS.md` и public website. Создан durable `context/` слой с current state, decisions, evidence ledger, history, next-work vector, session protocol и audit archive.

## Regression coverage

Добавлены suites для soak stabilization, control/dashboard state, Windows native OpenSSH/Sysnative, installer recovery, updater rollback, existing-device Repair, Telegram Repair/new-code UX, website/OpenSSH content и version/release consistency. Release tree проходит Linux full release checks и Windows PowerShell 5.1 validation.

## Acceptance matrix

Подтверждены external Microsoft RDP, Windows/Linux reboot recovery, multi-device simultaneous operation, failure isolation, Telegram OFF/ON/RESTART, dashboard auto-refresh/mobile layout, Win10 x64+x86 PowerShell/Sysnative, Windows Server 2019, server/client update rollback, Repair rollback, Defender coexistence, fast-path performance fix и pairing retry UX.

## Известные границы

`RL-006` оставался PARTIAL только по необязательному финальному Windows process-count после уже чистых пяти reconnect cycles. `SEC-004` не реконструировался искусственно, потому что старый revoked fixture уже отсутствовал.

## Packaging bug / why v1.2.1 exists

Release workflow `v1.2.0` выбирал tag target через commit, менявший `VERSION`, а не полный validated workflow HEAD. Исторический tag не переписывается. `v1.2.1` опубликован как полный согласованный release tree и является рекомендуемой версией линии `v1.2.x`.
