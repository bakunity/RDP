# Hermes RDP v1.2.0 — Full engineering history

Этот файл сохраняет расширенную инженерную историю релиза `v1.2.0`. Публичное описание GitHub Release намеренно короче.

## Stabilization baseline

`v1.2.0` был большим стабилизационным этапом после перехода с FRP на системный OpenSSH. Основная работа была направлена на recovery, совместимость Windows, transactional lifecycle, multi-device поведение, Telegram control plane, производительность RDP и проверяемость обновлений.

## Recovery и устойчивость

Live проверялись Windows reboot, Linux reboot, Windows-side transport loss, controller restart, dedicated Hermes sshd restart, repeated reconnect cycles, несколько независимых Windows devices и one-device failure isolation.

## Найденные control-plane bugs

- Stalled TLS client мог блокировать глобальный HTTPS API accept path. TLS handshake был перенесён в bounded per-connection worker, после чего параллельные health requests продолжали обслуживаться при намеренно зависшем соединении.
- Desired OFF + local ON мог зациклить transport-first reconciliation. Control polling был отделён от transport recovery, и fixture стал сходиться OFF/ON без искусственного restart.
- Pending command мог оставаться executing бесконечно. Добавлен deterministic timeout и защита от позднего stale result.

## Windows compatibility

### Windows 10 x64 + PowerShell x86

На реальном Windows 10 Pro x64 был воспроизведён запуск из `SysWOW64` PowerShell. Из-за WOW64 redirection native OpenSSH мог быть недоступен через обычный путь. Installer/Repair получили `Sysnative` path для native `ssh.exe` / `ssh-keygen.exe`, сохраняя canonical System32 path для SYSTEM Scheduled Task. Fresh install из x86 PowerShell прошёл end-to-end.

### Windows Server 2019

Исправлен ProductType gate, который ошибочно отклонял поддерживаемый Windows Server. Windows Server 2019 Datacenter прошёл fresh install, update с сохранением identity и реальный RDP.

### Existing-install guard

Повторное `Добавить ПК` на уже установленной машине перестало выполнять destructive mutation. До фикса этот путь мог остановить рабочую Scheduled Task до ожидаемой pairing failure.

## Transactional update

### Linux server

Server updater получил requested ref -> immutable SHA, consistent SQLite backup, backup app/config/systemd state и metadata, bounded health gate и automatic rollback. Live проверены успешный update с сохранением устройств/endpoints и deliberate failure с восстановлением предыдущего runtime.

### Windows client

Windows updater получил immutable candidate SHA, PowerShell parse до остановки runtime, Agent/Task snapshot, bounded stable readiness и automatic rollback. При успешном update сохраняются `device.json`, Device ID, private/public SSH key, `known_hosts` и назначенный RDP-порт.

## Existing-device Repair

Добавлен Repair для уже зарегистрированной Windows-машины без fresh pairing/rekey. Он сохраняет Device ID, API token, Ed25519 identity, `known_hosts` и назначенный порт. Live fixture с удалёнными Agent file + Scheduled Task был восстановлен с `REPAIR=PASS`; deliberate failure подтвердил `ROLLBACK=PASS`. При потере critical identity Repair намеренно останавливается вместо скрытого re-pair.

## Performance / telemetry

Был найден заметный RDP performance regression: тяжёлые WMI/NetTCPIP/process probes выполнялись слишком часто в telemetry loop и совпадали с micro-freeze. Heavy probes были вынесены из ordinary fast path, ресурсная telemetry стала реже, observation mode — bounded. Fast core измерялся десятками миллисекунд; пользователь подтвердил плавную работу после исправления.

## Multi-device / endpoint lifecycle

Проверено несколько simultaneous reverse SSH tunnels, отдельные persistent endpoints, два Microsoft RDP-сеанса одновременно, failure isolation, hard delete с отзывом API/SSH authorization и закрытием listener, а также безопасное повторное использование освобождённого порта.

## Telegram control / UX

Проверены OFF/ON/RESTART, server-authoritative listener truth, разделение desired/applied/tunnel state, automatic dashboard refresh, mobile layout, `ВОССТАНОВИТЬ КЛИЕНТ` и `НОВЫЙ КОД` для pairing retry.

## Security

Сохранена per-device Ed25519 model: private key остаётся на Windows, cross-device authorization запрещён, admin SSH `:22` отделён от Hermes sshd `:7000`, Defender exclusions не добавляются. Defender real-time coexistence проверена live.

## Документация и tests

Обновлены README, Architecture, Quick Start, install guides, Migration, Operations, Security, Troubleshooting, Testing A-to-Z, `VALIDATED_SCENARIOS.md` и public site. Добавлен durable `context/` слой и новые regression suites для soak stabilization, control state, Sysnative/native OpenSSH, installer recovery, updater rollback, Repair и Telegram UX.

## Acceptance boundary

Подтверждены external Microsoft RDP, Windows/Linux reboot recovery, multi-device simultaneous operation, failure isolation, Telegram OFF/ON/RESTART, Win10 x64+x86 PowerShell, Windows Server 2019, transactional server/client rollback, Repair rollback, Defender coexistence и fast-path performance fix.

`RL-006` оставался PARTIAL только по необязательному финальному Windows process-count после уже чистых reconnect cycles. `SEC-004` не реконструировался искусственно из-за отсутствующего старого revoked fixture.

## Packaging note

Исторический `v1.2.0` tag был создан release workflow не на полном validated release tree. Tag не переписывается. Полный согласованный tree stabilization baseline опубликован как `v1.2.1`, который рекомендуется для install/update.
