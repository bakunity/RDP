# Архитектура

## Роли

### Hermes server

Единственный специальный узел:

- `frps.service` принимает туннели клиентов;
- `hermes-rdp.service` содержит HTTPS API и Telegram bot;
- SQLite хранит реестр устройств, пары, телеметрию и команды;
- сервер распределяет уникальные RDP-порты.

### Windows client

Все компьютеры равноправны, включая первый:

- `frpc.exe` публикует локальный `127.0.0.1:3389`;
- `HermesRdpAgent.ps1` отправляет телеметрию и получает команды;
- Scheduled Task запускает агент от `SYSTEM` после загрузки;
- локальный state определяет, должен ли FRPC быть включён.

## Подключение устройства

1. Сервер создаёт одноразовый восьмисимвольный код.
2. Код действует 15 минут и может быть использован один раз.
3. Windows проверяет SHA-256 TLS-сертификата API.
4. Сервер выдаёт уникальные `device_id`, API token и RDP port.
5. Клиент сохраняет конфигурацию с ACL только для `SYSTEM` и Administrators.
6. Телеметрия начинает поступать каждые 3 секунды.

## Команды

Telegram не подключается к Windows напрямую:

1. кнопка записывает команду в SQLite;
2. Windows получает команду в ответе на следующий telemetry POST;
3. агент включает, выключает или перезапускает FRPC;
4. результат возвращается на сервер.

Поэтому выключение одного клиента не влияет на остальные.
