# Проверенные сценарии

Этот документ фиксирует фактически выполненные проверки без публикации секретов и реальных production-идентификаторов.

## Подтверждено

### Чистая серверная установка

- Debian x86_64;
- OpenSSH Server установлен;
- `hermes-rdp-sshd.service` и `hermes-rdp.service` active/enabled;
- `doctor` подтвердил API `1.1.0` и OpenSSH transport;
- FRP service и binary отсутствуют;
- база создана с SSH-полями;
- RDP-пул закрыт до подключения устройства.

### Windows pairing

- установщик запущен в PowerShell администратора;
- создан Ed25519 keypair;
- зарегистрирован Scheduled Task;
- reverse SSH-туннель запущен;
- первый endpoint назначен из стандартного пула.

### Внешнее подключение

- Microsoft Remote Desktop подключился с телефона;
- телефон использовал мобильные данные, а не локальную сеть Windows-ПК;
- подтверждён полный путь:

```text
mobile network → Linux server → reverse SSH → Windows RDP
```

### Работа без FRP

- `frps.service` отсутствует;
- `frps` binary отсутствует;
- Windows не использует `frpc.exe`;
- исключения Microsoft Defender для tunnel binary не требуются.

## Найденный дефект

Повторная установка поверх старого WinMon/FRP-каталога могла завершиться `Access denied` при рекурсивном копировании защищённого private key.

Правильное исправление:

- переносить legacy-каталог целиком;
- применять ACL fallback только к каталогу Hermes RDP;
- начинать pairing после успешной локальной подготовки.

## Ещё требуется

- второй Windows-ПК и порт `53390`;
- восстановление после перезагрузки Windows;
- `OFF`, `ON`, `RESTART`;
- `DELETE` и повторное использование освобождённого порта;
- recovery после перезагрузки сервера.

Когда пункт проходит, его нужно переносить в раздел «Подтверждено» с датой и кратким описанием результата.
